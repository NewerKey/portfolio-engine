How I keep this portfolio up to date using CI/CD

January 16, 2026

This site lives in two places:

  • a private repo where I write content in Obsidian (obsidian-vault)
  • a public repo that knows how to turn that content into a Hugo site and deploy it (portfolio-engine)

My goal:

When I push new notes to the private repo, the public site will rebuild itself and publish the changes, without me touching the public repo manually unless I want to make some visual changes.

Here’s how I put it together.

High-level flow#

In words:

  1. I write or update notes in Obsidian.
  2. I commit and push to the private vault repo.
  3. A GitHub Action in the private repo sends a signal to the public repo.
  4. A GitHub Action in the public repo:
    • pulls the latest content from the private repo
    • converts it from Obsidian format into Hugo-ready Markdown
    • replaces the site’s content/ directory
    • builds the Hugo site
    • deploys it to GitHub Pages

In diagram form:

Trigger Workflow for Private Repo#

In the private repo, I have a very small workflow whose only job is to ping the public repo when I push to main.

name: Trigger Portfolio Build

on:
  push:
    branches: [main]

jobs:
  trigger:
    runs-on: ubuntu-latest
    steps:
      - name: Trigger event to engine
        uses: peter-evans/repository-dispatch@v2
        with:
          token: ${{ secrets.PAT_TOKEN }}
          repository: NewerKey/portfolio-engine
          event-type: publish-event

In the public repo, you can find the workflow that builds and deploy

Small details that make this workable#

A few conventions that keep this from turning into a mess:

  • Content vs. engine separation
    • The private repo owns content.
    • The public repo owns config, theme, and deployment.
  • Front matter flag
    • I only publish notes that have publish: true in the front matter.
    • Everything else can live in the vault without accidentally going live.
  • Single token, carefully scoped
    • PAT_TOKEN is stored as a secret and used only for:
      • repository-dispatch from private → public
      • checking out the private repo from the public repo’s workflow
      • pushing the built site to the Pages branch

How it feels in daily use#

From my side, day to day, it’s simple:

  1. Open Obsidian, write or edit notes.
  2. Mark anything I want public with publish: true.
  3. Commit and push to the private repo’s main.

Within a short time, the portfolio reflects the changes—no manual copying, no rebuilding, no touching the public repo.

That’s exactly the kind of quiet, reliable automation I like: I can focus on writing more as I hope to do this year and improving the platform, and the pipeline quietly keeps everything in sync
